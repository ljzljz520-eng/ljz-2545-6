# 原创设计说明：江湾夜跑（移动优先）

## 设计立场
夜跑者在出门前最需要回答的问题不是“哪条路好看”，而是：
**此刻哪条路多长、多陡、和谁交叉、灯现在有没有亮、路上/终点有没有开门的补给。**
因此首页不做运营横幅，把整屏交给“筛选”；地图退到详情页，因为地图会诱导用户
用“看起来亮/看起来近”做判断，而缩放与简化恰恰会改变视觉判断——本设计把判定权
全部收回到服务端原几何与带时间的观察记录。界面明确声明：**不承诺安全**。

## 信息架构（三个主视图）
1. **路线筛选（默认）**：照明芯片（不限/良好/部分/观察为黑/冲突/无近期夜证）→
   距离、坡度 → 补给类型与“此刻营业” → 定位距离。卡片只放由证据支持的徽章。
2. **路线详情**：简化线地图（可切原线、可拖简化公差，指标数字不变）→
   冲突/过期/白天照片三条警示 → 公共注意 → 原几何指标 → 交叉点 →
   **可核查的观察证据清单** → 补给营业时段 → 我的集合/退出点 → 补充观察。
3. **我的集合**：收藏卡片显示公共侧几何/观察版本相对收藏基线的变化；
   离线待同步计数与“立即合并”；独立说明合并规则。

## 手机使用路径
1. 单拇指：顶部芯片横向点选；卡片整块可点；底部 Toast 反馈。
2. 定位：首选 GPS；**拒绝权限/超时/不支持 → 同一屏“手动输入位置”**，
   手动位置持久化，后续距离筛选与 GPS 完全同路径。示例坐标直接给在对话框里。
3. 离线：断网仍可收藏、改集合点/退出点/备注（localStorage + outbox），
   顶栏变“离线（编辑本地保存）”；恢复在线自动 `/collections/sync`，
   冲突字段给出“采用对方较新值”的提示。
4. 详情页“用我当前位置”一键把定位填进集合点；退出点按桩号（米）输入并即时校验范围。

## 键盘使用路径（与触控一一对应，非额外功能）
- Tab 顺序即操作顺序：主导航 → 照明芯片组 → 输入框 → 定位按钮 → 路线卡。
- 焦点态用高对比暖色描边（`:focus-visible`），卡片可聚焦，Enter/Space 进入详情；
  集合卡片同样是可聚焦的 `role="button"`。
- 对话框（手动位置）打开即聚焦首个输入框，Esc 关闭，确定按钮可 Enter 提交。
- 哈希路由 `#home / #collections / #about / #detail/:id` 可直接跳转，
  “说明”页列出键盘路径，方便只用键盘的用户核查。
- 状态变化用 `aria-live`（定位状态、在线/离线、列表计数）播报。

## 视觉语义
- 颜色仅编码观察结论：绿=点亮、橙=部分、红=观察为黑、紫=冲突、灰=无夜证；
  过期与“仅白天照片”用黄描边徽章，且始终伴随文字，不只依赖颜色。
- 暗色底降低夜间使用眩光；地图上路线发光描边只做装饰，交叉/补给/集合/退出各有独立符号。

## 数据/工程取舍
- SQLite + R*Tree：城市级数据足够，零外部服务，测试可内存复现。
- 几何版本与观察版本分离：路改了几何升 `geom_version` 并重建交叉/分段；
  照明是只追加观察，升 `obs_version`，旧收藏可同时看到两种“过期”。
- 预分段索引与实时求交并存：同一 API 暴露 benchmark，结果集一致才允许切换，
  避免“为了快而悄悄改变判断”。

## 明确不做的事
- 不做“安全评分/推荐安全路线”，只呈现可核查记录与公共注意；
- 不用白天照片点亮任何照明徽章；
- 不在客户端对简化几何重新计算距离/坡度/交叉；
- 不让个人离线编辑写入或覆盖公共注意。
