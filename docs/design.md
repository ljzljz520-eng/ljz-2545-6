# 潼川夜跑 · 原创设计说明

> 一个“城市夜跑”主题的路线筛选站原型。核心不是渲染漂亮的地图，而是**诚实地表达空间数据的时间性、覆盖范围与不确定性**：
> 照明是带时间戳和覆盖范围的**观察**，不是路线的静态属性；简化线只用于展示；距离/坡度/交叉点永远从原几何计算。

## 1. 设计立场（先于功能）

1. **“照明良好”是一条夜间观察，不是标签。**
   它必须同时满足：观察人在**夜间**实地到访（`nightVisit=true`）、记录为夜间照片（`photo=night`）、带有访问时间与覆盖区间 `[cumStart,cumEnd]` 与覆盖比例 `coverage`。
   白天照片只证明“灯柱存在”，**不能当夜间亮灯保证**，在详情里单独成组展示，不计入亮灯比例。
2. **观察会过期、会冲突，系统不替用户消除矛盾。**
   超过 14 天的夜间观察标 `stale`；同一路段近期“亮/暗”记录并存时标 `conflict`，两条记录都保留、给出可点击的观察对，**不取平均、不用新的一条静默覆盖旧的**。
3. **简化线（simplified geometry）只用于渲染。**
   距离、最大坡度、路线交叉点、补给退出点投影全部在 densify（≤5m 加密）后的**原几何**上计算。地图怎么缩放、用多大抽稀容差，都不会改变任何里程/坡度/判断。
4. **界面不承诺安全。**
   全站只说“可核查的观察与几何事实”，顶栏与详情页都有非安全声明：数据可能过期或矛盾，跑者自行判断。

## 2. 数据模型（虚构城市“潼川”，局部米坐标系）

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 河流障碍 `river.ring` | 多边形环 `y∈[-16,16]` | 河面宽 32m，是跨桥投影判定的“不可穿越面” |
| 桥 `bridges` | 矩形、桥面中线 | 西关桥 B1（x≈300）、东关桥 B2（x≈2200），桥边 `bridge=true` |
| 路线 `routes` | 顶点（含高程 z）、`closed`、`bridgeMarks`、`status` | R1 滨河环线 / R2 老铁路绿道 / R3 双桥训练线 / R4 城北坡线 / **R5 旧西岸线（archived，由 R1 接续）** |
| 观察 `observations` | `kind/status/coverage/cumStart/cumEnd/nightVisit/photo/visitedAt` | 见第 1 节；O3 与 O4 构成 R1 真实冲突，O5/O7 为白天记录 |
| 补给 `supplies` | 坐标、`hours`、饮水 | 支持 `24h`、`06:00-22:00`、`Mo-Fr ...; Sa-Su ...` 三种时段 |
| 公共注意 `notices` | 文本、位置、`version`、更新人 | 独立资源，只由维护接口 PATCH；**集合同步路径永不写它** |
| 个人集合 `collection` | `name / points{} / favorites{} / tombstones{}` | 服务端保存版本历史 `collection_revs(rev,doc)` |

几何在服务端经过三步派生（`server/catalog.js`）：
`原顶点 → densify(≤5m) → 长度/坡度(50m窗口)/定长100m分段/跨路线求交/退出点投影`。

## 3. API（`/api`，全部可用 `?now=...ISO` 注入时间做可重复验收）

- `GET /routes` 组合筛选：`maxKm`、`maxGradePct`、`lit=1`（近期夜间亮灯≥80% 且无冲突）、`supplyNow=1`（此刻有营业退出点）、`includeArchived`。
- `GET /routes/:id` 详情，带 `ETag`；观察或公共注意变化后指纹失效（304→200）。
- `POST /spatial/query` 空间半径查询，`mode=index | realtime`，返回命中与**耗时/网格单元/候选段/扫描边数**，用于直接比较。
- `POST /spatial/snap` 跨桥感知 GPS 吸附（见第 4 节）。
- `POST /observations` 新增观察（白天记录强制 `nightVisit=false`）。
- `GET/PATCH /notices` 公共注意独立维护，PATCH 版本递增。
- `GET /collection`、`POST /collection/sync`（`{baseRev,doc,force}` 三路合并）、`GET /collection/revs`（版本可核查）。

## 4. 跨桥投影（为什么河面 GPS 不能“就近落到岸边”）

河面宽 32m，普通手机横向误差常达 10–30m。若直接对每条路线做最近点投影，
一个真实在桥上、但被 GPS 漂到河面上方的点，会被错误吸到**河岸步道**（连线跨河），
导致“你在滨河步道上”的错误提示与错误里程。规则（`geometry.snapToRoutes`）：

1. 非桥边：若 `GPS → 垂足` 的连线穿越河流多边形，拒绝（`reject-crosses-river`）；
2. GPS 本身落在河内时，**只允许桥边**（`reject-in-river`）；
3. 桥边允许跨河；平局时桥优先；
4. 精度 `accuracy` 放宽判定半径；低精度位置标 `unconfident` 而不是自信报错点。

验收：河面点 `(300,0)` 吸到西关桥桥面，20 条岸边候选被全部拒绝（A1）。

## 5. 预先分段索引 vs 实时空间求交

| 维度 | `index` | `realtime` |
| --- | --- | --- |
| 策略 | 250m 网格表 + 100m 定长段做候选裁剪 | 全量遍历每条路线 densify 原几何 |
| 精确距离 | 候选**连续段合并**后，在原几何切片上算最近点 | 整条原几何算最近点 |
| 结果 | 12 个测试点与 realtime **路线与里程完全一致** | 同左 |
| 扫描边数 | 平均约为实时的 **12%** | 3617 边（5 条路线） |
| 适用 | 在线、数据稳定、点查询量大 | 数据频繁变动或需要绝对可信的对照基准 |

要点：**索引只负责缩小候选集，距离数学只有一套**。因此“用了索引”不改变判断，只改变耗时；
`test/bench-spatial.js` 同时断言两模式结果一致，防止索引悄悄改变路线判断。

## 6. 个人集合点：离线编辑与公共路线更新分别合并

- 本地（localStorage）维护集合文档 + 待同步 `outbox`，离线时所有编辑**先本地生效并入队**，绝不假装同步成功。
- 同步是**字段级三路合并** `(base, server, client)`：
  - 两设备改**不同点**或同一点的**不同字段**（如 A 改坐标、B 改名称）→ 自动合并，无冲突；
  - 同一字段两端都改 → `409`，UI 让用户明确“用谁的”，再以 `force` 提交（`force` 时冲突字段取客户端值并留痕）；
  - 删除用墓碑：一端删、另一端改同一点 → 报冲突而非静默复活/丢失。
- **公共注意 notices 不属于集合文档**：集合同步的任何路径都不写 notices；公共路线更新走独立 PATCH，二者互不覆盖（A4b/A9）。

## 7. 提示定位、数据过期、失去定位权限

- **定位提示**：成功吸附后提示“路线 + 里程 + 是否在桥上 + 距离 + 精度是否不肯定 + 拒绝了多少跨河候选”，可核查。
- **数据过期**：列表顶部横幅汇总冲突与超期比例；详情按 50m 段展示 亮/暗/过期/无证据/冲突 五态与最近夜间观察时间。
- **失去定位权限**：拒绝（code 1）/不可用（2）/超时（3）分别给出文案，并自动展开**手动入口**（直接输坐标），不依赖系统权限也能用；手动坐标走同一套跨桥吸附（A8）。
- **网络恢复**：`online` 事件自动重放 `outbox` 同步、刷新列表；观察上报在离线时明确失败、不造假成功。

## 8. 手机使用路径（移动优先）

底部 4 个标签：**路线 / 地图 / 集合 / 观察·说明**，单手可达。

1. 打开即落在“路线”：大拇指标题下直接是筛选卡（距离滑杆 → 坡度滑杆 → “只要近期夜间亮灯”“此刻有营业补给”开关 → 应用），结果卡显示亮灯/坡度/营业/交叉点徽章与不符原因。
2. 点路线卡 → 底部抽屉看详情：距离、坡度、交叉点、照明五态、冲突观察对、白天照片单列、此刻补给退出点、公共注意，底部可一键离线收藏。
3. “地图”标签：定位我 / 比较索引与实时 / 手动入口；SVG 示意地图画河、桥、路线、营业补给与吸附结果。
4. “集合”标签：离线添加集合点、看待同步队列、手动同步、字段冲突时就地选择。
5. “观察·说明”：上报时必须选“夜间实地”还是“白天路过”，提交后文案明确是否计入照明；折叠面板解释方法论与安全声明。

## 9. 键盘使用路径（不依赖鼠标/触屏）

- 进入页面可按 `Tab` 到“跳到主内容”跳转链接，绕过品牌区。
- `1`–`4`：切换四个标签页；`F`：聚焦距离筛选；`Enter`：应用筛选；
- `L`：触发定位；`M`：展开手动入口并聚焦坐标；`S`：在集合页同步；`Esc`：关闭详情抽屉。
- 所有交互元素是原生 `button/input/select/summary`，有可见 `:focus-visible` 焦点环；状态文本挂 `aria-live`。

## 10. “推荐”为什么可核查

- 每条路线给出**构成推荐的原始量**：原几何距离、50m 窗口最大坡度、亮/暗/过期/冲突的 50m 段比例、证据条数与最近夜间观察时间、此刻开门的补给退出点（含营业时间原文与距离）。
- 冲突给出**观察 ID 对与里程位置**；白天记录单列且明示“不计入”。
- 服务端保存观察记录与集合的**版本历史**（`/collection/revs`、notice `version`），路线详情用 ETag 区分“数据未变”与“已更新”。
- 所有筛选可用 `?now=` 注入时间复现，验收脚本无随机依赖。
- 文案统一避免“安全/最安全/放心跑”，改为“近期夜间记录亮灯 X%”“有记录不亮”“证据已过期”。
